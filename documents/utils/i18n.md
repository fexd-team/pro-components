# i18n 国际化

`@fexd/pro-components` 提供了一套完整的国际化方案，基于 `@fexd/tools` 的 `I18n` 类构建，支持全局实例、按需 scope、语言切换自动响应、JSX 插值和数字格式化等功能。

## 语言支持

内置 **6 种语言**，覆盖东南亚主要市场：

| 语言代码          | 语言     | 文件                 |
| ----------------- | -------- | -------------------- |
| `zh-CN` / `zh_CN` | 简体中文 | `locales/zh-CN.json` |
| `en-US` / `en_US` | 英语     | `locales/en-US.json` |
| `id-ID` / `id_ID` | 印尼语   | `locales/id-ID.json` |
| `ms-MY` / `ms_MY` | 马来语   | `locales/ms-MY.json` |
| `vi-VN` / `vi_VN` | 越南语   | `locales/vi-VN.json` |
| `th-TH` / `th_TH` | 泰语     | `locales/th-TH.json` |

> 语言代码支持 `-`（kebab-case）和 `_`（snake_case）两种格式，两者等价。

## 核心实例

### globalI18n — 全局实例

全局单例，所有 Pro 组件内部共享。支持 fallback 链和增量配置。

```tsx | pure
import { globalI18n, t } from '@fexd/pro-components'

// 通过全局实例翻译
const msg = globalI18n.t('utils.confirm') // "确认"

// t 是 globalI18n.t 的简写别名
const ok = t('utils.okText') // "确认"
```

#### 切换语言

```tsx | pure
// await globalI18n.applyLng('zh-CN')
// 或
// await globalI18n.applyLng('en-US')
```

#### 增量配置翻译资源

```tsx | pure
// 追加新翻译键（默认 supplement 模式，不覆盖已有值）
globalI18n.applyConfig({
  types: {
    default: {
      resources: {
        'zh-CN': { myModule: { title: '我的模块' } },
        'en-US': { myModule: { title: 'My Module' } },
      },
    },
  },
})

// 强制覆盖已有值
globalI18n.applyConfig(
  {
    types: {
      default: {
        resources: {
          'zh-CN': { myModule: { title: '重写标题' } },
        },
      },
    },
  },
  { mode: 'override' },
)
```

> `globalI18n` 的 `defaultApplyMode` 为 `supplement`，增量配置**不会覆盖**已有翻译。显式指定 `mode: 'override'` 可强制覆盖。

> ⚠️ **重要提示**：本节的 `supplement` vs `override` 说明适用于业务侧对 `globalI18n` 的调用，**不影响**组件库内部行为。组件库内部的 `applyConfig` 已指定 `priority: 2`，优先级始终高于业务侧的默认 `supplement` 调用。

### ⚠️ supplement 模式潜在问题

`globalI18n` 默认使用 `supplement` 模式，意味着 `applyConfig` 注入的翻译**只在 key 不存在时生效**，已有翻译永远不会被覆盖。这在以下场景会产生问题：

| 场景 | 问题 | 原因 |
| --- | --- | --- |
| 业务侧覆盖组件库翻译 | ❌ 业务侧的翻译**不生效** | 组件库的翻译已通过 `supplement` 模式注册，业务侧的覆盖被忽略 |
| 第三方组件库更新翻译 key | ❌ 新 key 无法覆盖旧的错误翻译 | 组件库升级后 key 未变但内容变了，新值不生效 |
| 多模块翻译冲突 | ❌ 后注册的模块永远拿不到覆盖权 | 后加载的模块无法覆盖先加载模块的同名 key |
| 灰度 / A/B 翻译测试 | ❌ 测试翻译无法覆盖线上翻译 | 测试环境配置的翻译被 `supplement` 模式屏蔽 |

**根本原因**：`supplement` 模式的语义是「补充缺失的键，不覆盖已有键」，而不是「按注入顺序决定优先级」。

### ✅ 业务侧强覆盖方案

当业务侧需要**确保自己的翻译优先级最高**时，应使用 `mode: 'override'`：

```tsx | pure
import { globalI18n } from '@fexd/pro-components'

// ✅ 方案 1：单 key 强覆盖（推荐，精准控制）
// await globalI18n.applyConfig(
  {
    types: {
      default: {
        resources: {
          'zh-CN': { 'utils.confirm': '确定' }, // 覆盖组件库的默认值
          'en-US': { 'utils.confirm': 'Confirm' },
        },
      },
    },
  },
  { mode: 'override' }, // 强制覆盖
)

// ✅ 方案 2：批量强覆盖（适用于初始化时一次性注册）
// await globalI18n.applyConfig(
  {
    types: {
      default: {
        resources: {
          'zh-CN': {
            'utils.confirm': '确定',
            'utils.cancelText': '取消',
            // ...更多 key
          },
          'en-US': {
            'utils.confirm': 'Confirm',
            'utils.cancelText': 'Cancel',
          },
        },
      },
    },
  },
  { mode: 'override' },
)

// ✅ 方案 3：创建业务专用实例（隔离，不影响全局）
import { I18n } from '@fexd/pro-components'
const businessI18n = new I18n({
  fallback: [globalI18n], // 先查全局，再查业务
  types: {
    default: {
      resources: {
        'zh-CN': { 'utils.confirm': '确定' }, // 业务侧强覆盖
      },
    },
  },
})
// 组件中使用 businessI18n 而非 globalI18n
```

### 📊 优先级决策指南

| 需求                      | 模式                 | 做法                                                  |
| ------------------------- | -------------------- | ----------------------------------------------------- |
| 补充组件库缺失的翻译      | `supplement`（默认） | `globalI18n.applyConfig({...})`                       |
| 覆盖组件库的翻译          | `override`           | `globalI18n.applyConfig({...}, { mode: 'override' })` |
| 组件库翻译 + 业务翻译共存 | `supplement`         | 先注册组件库，再补充业务 key                          |
| 业务翻译优先级最高        | `override`           | 业务初始化时 `applyConfig` 设置 `mode: 'override'`    |
| 完全隔离的业务翻译        | 新 `I18n` 实例       | `new I18n({ fallback: [globalI18n], types: {...} })`  |

### 🔑 组件库内部 vs 业务侧优先级

组件库内部调用 `applyConfig` 时已指定 `priority: 2`：

```tsx | pure
// @fexd/pro-form / @fexd/pro-table 内部
import { globalI18n, createSharedHook } from '@fexd/pro-utils'

globalI18n.applyConfig(
  { types: { default: { resources: builtInLocaleMap } } },
  { mode: 'supplement', priority: 2 }, // priority: 2
)
```

业务侧调用 `applyConfig` 时的优先级对比：

| 调用方             | 模式         | priority | 最终优先级               |
| ------------------ | ------------ | -------- | ------------------------ |
| 组件库             | `supplement` | `2`      | 中等（优先于默认 0）     |
| 业务侧（默认）     | `supplement` | `0`      | 最低                     |
| 业务侧（显式）     | `supplement` | `3`      | 高于组件库               |
| 业务侧（override） | `override`   | 任意     | **强制覆盖，无视优先级** |

> **结论**：如果业务侧需要使用默认的 `supplement` 模式但不想被覆盖，可以显式设置 `priority: 3`（大于组件库的 `2`）。如果业务侧需要 100% 确定覆盖，使用 `mode: 'override'` 是最可靠的方案。

## t 函数 — 翻译

`globalI18n.t` 的简写别名，支持三种特殊类型。

### 关键设计：使用 options 而非 key 后缀

> 类型通过 `t(key, { '@type': 'xxx' })` 的 options 参数指定，key 始终保持纯净的翻译路径。

```tsx | pure
// ❌ 旧写法（不推荐）：type 混入 key，不利于翻译管理
t('1000000@number')
t('欢迎，{{name}}@jsx', { name: '张三' })

// ✅ 新写法（推荐）：key 是纯净的翻译路径，类型通过 options 指定
t('1000000', { '@type': 'number' })
t('greeting.welcome', { '@type': 'jsx', name: <strong>张三</strong> })
```

### 1. 普通翻译（默认）

```tsx | pure
import { t } from '@fexd/pro-components'

t('utils.confirm') // → "确认"
t('utils.confirm', { count: 5 }) // → 支持参数插值
```

### 2. 数字格式化 — `{ '@type': 'number' }`

自动根据当前语言格式化数字，**支持超大数字**（突破 JavaScript Number 精度限制）：

```tsx | pure
t('total.amount', { '@type': 'number' }) // → "1,000,000.0001"
t('total.amount', { '@type': 'number', locale: 'id' }) // → "1.000.000,0001"（印尼格式）
t('total.amount', { '@type': 'number', toFixed: 2 }) // → "1,000,000.00"（自定义精度）

// 超大数字（超出 Number.MAX_SAFE_INTEGER 仍保持精度）
t('big.number', { '@type': 'number' }) // → "12,345,678,987,654,321.0001"
```

> 内部对超出 `Number.MAX_SAFE_INTEGER` 的数字使用 BigNumber.js 模拟 `toLocaleString`，确保精度不丢失。

**支持参数**：

| 参数      | 说明         | 类型                                     | 默认值               |
| --------- | ------------ | ---------------------------------------- | -------------------- |
| `locale`  | 数字语言环境 | `'zh' \| 'id' \| 'en' \| 'ms' \| string` | 当前语言             |
| `toFixed` | 固定小数位数 | `number`                                 | 无限制（最多 20 位） |

### 3. JSX 插值 — `{ '@type': 'jsx' }`

在翻译文本中嵌入 React 组件：

```tsx | pure
import { globalI18n } from '@fexd/pro-components'

// 配置翻译资源
globalI18n.applyConfig({
  types: {
    jsx: {
      resources: {
        'zh-CN': { 'greeting.welcome': '欢迎，{{name}}' },
        'en-US': { 'greeting.welcome': 'Welcome, {{name}}' },
      },
    },
  },
})

// await globalI18n.applyLng('zh-CN')

// 渲染 JSX 插值
const result = globalI18n.t('greeting.welcome', {
  '@type': 'jsx',
  name: <strong>张三</strong>,
})
// → <span>欢迎，<strong>张三</strong></span>
```

**使用场景**：

```tsx | pure
// 链接组件
t('agreement.text', {
  '@type': 'jsx',
  link: <a href="/terms">用户条款</a>,
})
// 翻译资源：'agreement.text': '我同意{{link}}'

// 图标组件
t('warning.message', {
  '@type': 'jsx',
  icon: <ExclamationCircleOutlined style={{ color: '#faad14' }} />,
})
```

### 4. 命名空间 — `{ '@namespace': 'xxx' }`

当翻译 key 在多个模块间可能冲突时，使用命名空间隔离：

```tsx | pure
t('deleteConfirm', { '@namespace': 'myModule' }) // 从 myModule 的翻译资源查找
t('deleteConfirm', { '@namespace': 'common' }) // 从 common 的翻译资源查找
```

## React 集成

### useI18n / useTranslation — Hook

在函数组件中获取翻译函数，语言切换时自动重新渲染：

```tsx | pure
import React from 'react'
import { useI18n } from '@fexd/pro-components'

function MyComponent() {
  const { t, jsxT } = useI18n()
  // 或使用别名
  // const { t, jsxT } = useTranslation()

  return (
    <div>
      <h1>{t('utils.confirm')}</h1>
      {/* jsxT 内部使用 '@type': 'jsx' */}
      <p>{jsxT('greeting.welcome', { name: <strong>张三</strong> })}</p>
    </div>
  )
}
```

| 返回值               | 说明                                                         |
| -------------------- | ------------------------------------------------------------ |
| `t(key, options?)`   | 普通翻译函数，支持 `@type` 和 `@namespace`                   |
| `jsxT(key, ...args)` | JSX 插值翻译（等同于 `t(key, { '@type': 'jsx', ...args })`） |

### withI18n — HOC

将翻译函数注入组件 props，支持加载等待：

```tsx | pure
import React from 'react'
import { withI18n } from '@fexd/pro-components'

function MyComponent({ t }) {
  return <div>{t('utils.confirm')}</div>
}

// 不带 fallback
const Wrapped1 = withI18n()(MyComponent)

// 带 loading 占位
const Wrapped2 = withI18n({
  fallback: <div>加载中...</div>,
})(MyComponent)
```

> `withI18n` 会在语言资源未就绪时显示 fallback，语言切换后自动更新。

### FormattedMessage — 组件

直接渲染翻译文本：

```tsx | pure
import { FormattedMessage } from '@fexd/pro-components'

<FormattedMessage value="utils.confirm" />
<FormattedMessage value="utils.confirm" config={{ count: 5 }} />
```

## numberTranslate — 数字格式化

独立于 `t` 的数字格式化函数，支持 locale 和精度配置：

```tsx | pure
import { numberTranslate } from '@fexd/pro-components'

// 基本格式化
numberTranslate('1000000') // → "1,000,000"
numberTranslate('1000000', { locale: 'id' }) // → "1.000.000"

// 自定义精度

// 非数字原样返回
numberTranslate('abcd') // → "abcd"
```

## I18n 类

从 `@fexd/tools` 导出的 `I18n` 类，用于创建自定义 i18n 实例：

```tsx | pure
import { I18n } from '@fexd/pro-components' // 或 '@fexd/tools'

const customI18n = new I18n({
  // 内置资源（支持多种语言格式）
  types: {
    default: {
      resources: {
        'zh-CN': { title: '标题' },
        'en-US': { title: 'Title' },
        zh_CN: { title: '标题' }, // 也支持 snake_case
      },
    },
    // JSX 类型
    jsx: {
      resources: {
        'zh-CN': { 'greeting.welcome': '欢迎，{{name}}' },
      },
      format: jsxTranslate, // JSX 格式化函数
    },
    // 数字类型
    number: {
      resources: false, // 不使用资源，直接格式化
      format: numberTranslate,
    },
  },
  // fallback 链
  fallback: [anotherI18nInstance],
  // 配置模式：'supplement'（不覆盖）或 'override'（覆盖）
  defaultApplyMode: 'supplement',
})

// 切换语言
// await customI18n.applyLng('zh-CN')

// 监听语言变化
customI18n.eventBus.on('change', (localeKey: string) => {
  console.log('语言切换为：', localeKey)
})
```

### I18n 配置项

| 属性               | 说明                                | 类型                                      | 默认值       |
| ------------------ | ----------------------------------- | ----------------------------------------- | ------------ |
| `types`            | 翻译类型定义                        | `Record<string, { resources?, format? }>` | `{}`         |
| `fallback`         | fallback 链                         | `I18n[]`                                  | `[]`         |
| `defaultApplyMode` | 默认配置模式                        | `'supplement' \| 'override'`              | `'override'` |
| `splitByDot`       | 是否按 `.` 拆分 key（自动命名空间） | `boolean \| 'auto'`                       | `'auto'`     |

### applyConfig 选项

| 属性 | 说明 | 类型 | 默认值 |
| --- | --- | --- | --- |
| `mode` | 合并模式 | `'supplement' \| 'override'` | `config.defaultApplyMode` |
| `priority` | 补充优先级（仅在 `mode='supplement'` 时生效） | `number` | `0` |

**priority 行为**（仅在 `mode='supplement'` 时生效）：

| 当前 priority | 已有 priority | 结果                   |
| ------------- | ------------- | ---------------------- |
| `3`           | `2`           | **覆盖**（当前更高）   |
| `2`           | `3`           | **不覆盖**（已有更高） |
| `3`           | `3`           | 不覆盖（先到先得）     |
| `0`           | `2`           | 不覆盖（已有更高）     |

### I18n 实例方法

| 方法 | 说明 | 参数 | 返回值 |
| --- | --- | --- | --- |
| `applyLng(lng)` | 切换语言 | `string` | `Promise<void>` |
| `applyConfig(config, options?)` | 增量配置资源 | `I18nConfig`, `{ mode?, priority? }` | `Promise<void>` |
| `t(str, rawOptions?)` | 翻译 | `string`, `{ '@type'?, '@namespace'?, '@splitByDot'? }` | `string \| ReactNode` |
| `eventBus` | 事件总线 | - | `EventBus` |

## t() 方法选项详解

`I18n.t()` 接收完整的选项对象，支持以下特殊键：

```tsx | pure
t('key', {
  '@type': 'jsx', // 指定类型：'default' | 'jsx' | 'number' | 自定义类型名
  '@namespace': 'myModule', // 指定命名空间
  '@splitByDot': false, // 覆盖 splitByDot 配置
  count: 5, // 普通参数，用于模板插值 {{count}}
  locale: 'id', // 类型特定的参数（如 number 类型）
  name: <strong>张三</strong>, // JSX 类型的节点参数
})
```

| 选项          | 说明                                    | 说明                                     |
| ------------- | --------------------------------------- | ---------------------------------------- |
| `@type`       | 翻译类型，匹配 `types` 配置中的键名     | `'default'`（默认）、`'jsx'`、`'number'` |
| `@namespace`  | 命名空间，影响资源查找路径              | `'myModule'`、`'common'` 等              |
| `@splitByDot` | 是否按 `.` 拆分 key 为 namespace:subKey | `true` / `false` / `'auto'`              |
| 其他参数      | 模板插值参数                            | 对应 `{{paramName}}`                     |

### 使用示例

```tsx | pure
// 类型示例：数字、JSX
t('price', { '@type': 'number', locale: 'zh' }) // 数字格式化
t('greeting', { '@type': 'jsx', name: <User /> }) // JSX 插值
t('confirm.text') // 普通翻译

// 命名空间示例
t('deleteConfirm', { '@namespace': 'order' }) // 订单模块的删除确认
t('deleteConfirm', { '@namespace': 'user' }) // 用户模块的删除确认

// 组合使用
t('price', { '@type': 'number', '@namespace': 'global' })
```

### splitByDot 自动拆分

当 `splitByDot` 为 `'auto'`（默认）时，key 中的 `.` 会自动拆分为 namespace 和 subKey：

```tsx | pure
// 以下两种写法等价：
t('myModule:title')
t('title', { '@namespace': 'myModule' })

// 嵌套参数也支持
t('order.deleteConfirm', { '@type': 'jsx', name: <strong>订单</strong> })
```

## 多层级 i18n 架构

Pro 组件库采用 **三层 i18n 架构**：

```
全局层 (globalI18n)        — 基础翻译 + 数字格式化 + JSX 插值
   ↑ fallback
作用域层 (scopeI18n)       — 模块级翻译（form / table）
   ↑ fallback
Provider/组件级配置         — 运行时 locale 属性 + 动态覆盖
```

### ⚠️ 替换局部语言包（table/form）的正确方法

由于 `scopeI18n`（模块级实例）自身就包含 `builtInLocaleMap`，翻译查找顺序为：

1. `scopeI18n.types.default.resources` (builtInLocaleMap) ← **最高优先级**
2. `scopeFallbackI18n.types.default.resources` (也是 builtInLocaleMap)
3. `globalI18n` 的 resources ← **最低优先级**

> **结论**：`globalI18n.applyConfig()` **无法覆盖**模块内置翻译，因为 `scopeI18n` 自己的 `resources` 优先级最高。

**唯一正确方法**：通过 `ConfigProvider` 的 `locale` 属性

```tsx | pure
import { ConfigProvider } from '@fexd/pro-components'

// 覆盖 table 模块的翻译
;<ConfigProvider
  localeKey="zh-CN"
  locale={{
    table: {
      actions: {
        deleteConfirm: '确定要删除吗？', // 覆盖内置翻译
        multipleDeleteConfirm: (count) => `确定删除选中的 ${count} 项吗？`,
      },
      editField: {
        add: '新建', // 覆盖"新增"
        edit: '修改', // 覆盖"编辑"
      },
    },
    form: {
      pleaseEnter: '请输入内容',
      requiredMessage: '此项为必填',
    },
  }}
>
  <ProTable />
  <ProForm />
</ConfigProvider>
```

**原理**：`useLocales` Hook 中的 `getTranslatedText` 函数会优先读取 `ConfigProvider` 的 `locale` 属性，然后才 fallback 到 `scopeI18n` / `globalI18n`。

### 各模块的翻译 key 范围

**Provider 层** (`@fexd/pro-provider`)：

## translateFallback 兜底回调

`translateFallback` 是 I18n 实例的**最后一道防线**。当所有翻译资源（包括 fallback 链）都找不到翻译时，会调用 `translateFallback` 回调函数。

### 调用时机

```
t('key')
   ↓ 查找当前实例 resources
   ↓ 找不到
   ↓ 查找 fallback[0].t('key')
   ↓ 找不到
   ↓ 查找 fallback[1].t('key')
   ↓ 找不到
   ↓ ...
   ↓ 所有 fallback 都找不到
   ↓ 调用 translateFallback('key', options)
   ↓ 返回结果（如果 translateFallback 返回 undefined，则返回 key 本身）
```

### 配置方式

```tsx | pure
import { I18n } from '@fexd/pro-components'

const i18n = new I18n({
  // 配置 translateFallback 回调
  translateFallback: (key, options) => {
    // 返回自定义的兜底文本
    return `[Missing: ${key}]`
  },
  types: {
    default: {
      resources: {
        zh_CN: {
          // 翻译资源
        },
      },
    },
  },
})
```

### 回调函数签名

```tsx | pure
type TranslateFallback = (key: string, options: Record<string, any>) => string | ReactNode | undefined
```

| 参数       | 说明                                                   | 类型                               |
| ---------- | ------------------------------------------------------ | ---------------------------------- |
| `key`      | 缺失的翻译 key                                         | `string`                           |
| `options`  | 翻译时的 options 参数（包含 `@type`、`@namespace` 等） | `Record<string, any>`              |
| **返回值** | 兜底文本，可以是字符串或 JSX 节点                      | `string \| ReactNode \| undefined` |

### 行为规则

| 场景                             | translateFallback 是否调用 |
| -------------------------------- | -------------------------- |
| 当前实例找到翻译                 | ❌ 不调用                  |
| fallback 链中找到翻译            | ❌ 不调用                  |
| 所有实例都找不到                 | ✅ 调用                    |
| @type 格式化失败                 | ✅ 调用                    |
| translateFallback 返回 undefined | 返回 key 本身              |
| translateFallback 返回字符串     | 返回该字符串               |
| translateFallback 返回 JSX       | 返回该 JSX 节点            |

### 使用场景

#### 1. 开发环境：输出警告，方便发现缺失的翻译

```tsx | pure
const isDevelopment = process.env.NODE_ENV === 'development'

const i18n = new I18n({
  translateFallback: (key) => {
    if (isDevelopment) {
      // 开发环境：输出警告并返回带标记的文本
      console.warn(`[i18n] ⚠️ Missing translation key: ${key}`)
      return `[⚠️ ${key}]`
    }
    // 生产环境：直接返回 key，避免暴露内部结构
    return key
  },
})
```

#### 2. 生产环境：返回友好的占位文本

```tsx | pure

    return `[${lastPart}]`
  },
})

```

#### 3. 根据 options 返回不同的兜底文本

```tsx | pure

    }

```

#### 4. 返回 JSX 节点（用于 @type: 'jsx'）

```tsx | pure

  translateFallback: (key) => {

    jsx: {
      format: (str) => str,
    },
  },

// 使用时
```

### 与 fallback 链的关系

```tsx | pure

  types: {
    default: {
      resources: {
        zh_CN: { fromFallback: '来自 Fallback' },
      },
    },
  },
})

  fallback: [fallbackI18n],
  translateFallback: (key) => {

  },

    default: {
      resources: {
        zh_CN: {
          // 空
        },
      },
    },
  },
})

// await I18n.applyLanguage('zh_CN')

// fallbackI18n 有的 key，不调用 translateFallback

// console.log 不会输出

// 所有实例都没有的 key，调用 translateFallback
mainI18n.t('missing.key') // → '[兜底：missing.key]'
// console.log 输出：translateFallback 被调用
```

### 完整翻译查找流程

```
t('key')
   │
   ├─→ 1. 当前实例 resources
   │     └─→ 找到 → 返回 ✅
   │     └─→ 没找到 ↓
   │
   ├─→ 2. fallback[0].t('key')
   │     └─→ 找到 → 返回 ✅
   │     └─→ 没找到 ↓
   │
   ├─→ 3. fallback[1].t('key')
   │     └─→ 找到 → 返回 ✅
   │     └─→ 没找到 ↓
   │
   ├─→ ...
   │
   ├─→ 4. 所有 fallback 都找不到
   │     └─→ 调用 translateFallback('key', options)
   │           └─→ 返回值 !== undefined → 返回 ✅
   │           └─→ 返回 undefined → 返回 key 本身 ✅
```

## Fallback 机制详解

`I18n` 的 fallback 机制是多层 i18n 架构的核心。当当前实例找不到翻译时，会**按顺序**查找 fallback 链中的实例。

### Fallback 查找流程

```
scopeI18n.t('key')
   ↓ 找不到
scopeFallbackI18n.t('key')  // fallback[0]
   ↓ 找不到
globalI18n.t('key')         // fallback[1]
   ↓ 找不到
返回 key 本身
```

### 核心规则

| 规则                    | 说明                                                                       |
| ----------------------- | -------------------------------------------------------------------------- |
| **按顺序查找**          | fallback 数组中的实例按索引顺序查找（`fallback[0]` → `fallback[1]` → ...） |
| **找到即停止**          | 只要有一个实例返回了翻译结果，就停止查找                                   |
| **空值会 fallback**     | 空字符串 `''`、`null`、`undefined` 都会触发 fallback                       |
| **找不到返回 key**      | 所有实例都找不到时，返回 key 本身（如 `'nonexistent.key'`）                |
| **@type 也会 fallback** | 数字格式化、JSX 插值等类型也会沿 fallback 链查找                           |
| **语言切换后仍然有效**  | fallback 链在语言切换后继续保持                                            |

### 示例代码

```tsx | pure
import { I18n } from '@fexd/pro-components'

// 1. 创建 fallback 实例（底层）
const globalI18n = new I18n({
  types: {
    default: {
      resources: {
        zh_CN: { utils: { confirm: '确认', cancel: '取消' } },
      },
    },
  },
})

// 2. 创建带 fallback 的实例（上层）
const scopeI18n = new I18n({
  fallback: [globalI18n], // 设置 fallback 链
  types: {
    default: {
      resources: {
        zh_CN: {
          // 只有 greeting，没有 utils
          greeting: '你好',
        },
      },
    },
  },
})

// await I18n.applyLanguage('zh_CN')

// scopeI18n 有自己的 greeting
scopeI18n.t('greeting') // → '你好'

// scopeI18n 没有 utils.confirm，fallback 到 globalI18n
scopeI18n.t('utils.confirm') // → '确认'

// 两个实例都没有的 key，返回 key 本身
scopeI18n.t('nonexistent.key') // → 'nonexistent.key'
```

### Pro 组件库的多层 Fallback 架构

```tsx | pure
// packages/table/src/plugins/config/useLocales.tsx
const scopeFallbackI18n = new I18n({
  types: {
    default: {
      resources: builtInLocaleMap, // 组件库内置翻译
    },
  },
})

const scopeI18n = new I18n({
  fallback: [scopeFallbackI18n, globalI18n], // 两层 fallback
  types: {
    default: {
      resources: builtInLocaleMap, // 模块实例自己的翻译
    },
  },
})
```

**查找顺序**：

1. `scopeI18n.types.default.resources`（模块实例自己的翻译）← **优先级最高**
2. `scopeFallbackI18n.types.default.resources`（组件库内置翻译）
3. `globalI18n.types.default.resources`（全局翻译）← **优先级最低**

> ⚠️ **重要**：这就是为什么 `globalI18n.applyConfig()` 无法覆盖组件库内置翻译的原因！

### Fallback 行为测试用例

以下是 12 个关键场景的测试验证（已通过）：

```tsx | pure

expect(mainI18n.t('confirm')).toBe('确认')

// 场景 10: Pro 组件库的多层架构模拟
expect(scopeI18n.t('table.actions.delete')).toBe('确定删除？') // scopeI18n 覆盖
expect(scopeI18n.t('table.actions.edit')).toBe('编辑') // scopeFallbackI18n
```
