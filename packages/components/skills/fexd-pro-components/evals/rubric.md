# 评分标准

每个测试用例按以下维度评分，每项 0-2 分。

## 评分维度

### 1. 导入正确性（0-2）

- **2 分**：从 `@fexd/pro-components` 统一导入，无多余导入
- **1 分**：导入正确但有冗余，或从子包导入
- **0 分**：导入错误的包名或组件名

### 2. API 准确性（0-2）

- **2 分**：Props 名称、类型、用法完全正确
- **1 分**：大部分正确，有少量错误（如属性名拼写）
- **0 分**：使用了不存在的 API 或完全错误的用法

### 3. 最佳实践（0-2）

- **2 分**：遵循推荐实践（命令式优先、确认操作、占位文案等）
- **1 分**：部分遵循，有改进空间
- **0 分**：违反关键最佳实践

### 4. 响应格式（0-2）

- **2 分**：回调返回正确的 `{ success, data, total }` 格式
- **1 分**：格式大致正确但不完整
- **0 分**：返回格式完全错误

### 5. 代码完整性（0-2）

- **2 分**：可运行的完整代码，包含必要的错误处理
- **1 分**：代码基本完整但缺少错误处理或边界情况
- **0 分**：代码片段不完整，无法运行

## 总分标准

| 总分 | 等级 | 说明                   |
| ---- | ---- | ---------------------- |
| 9-10 | A    | 优秀，完全符合文档规范 |
| 7-8  | B    | 良好，有少量偏差       |
| 5-6  | C    | 及格，需要人工修正     |
| 3-4  | D    | 较差，多处错误         |
| 0-2  | F    | 不可用                 |

## 关键检查项

生成代码的致命错误（一票否决降至 C 以下）：

- 使用了不存在的组件或 API
- 从错误的包导入
- onQuery 不返回 `{ success, data, total }` 格式
- 危险操作无确认
